# Эмулятор языка оболочки ОС

**Дисциплина:** Конфигурационное управление
**Группа:** ИКБО-32-25
**Вариант:** 26
**Выполнено:** Этап 1 (REPL), Этап 2 (Конфигурация)

## 1. Общее описание

Эмулятор языка оболочки ОС — приложение с графическим
интерфейсом, которое имитирует работу командной строки
UNIX-подобной операционной системы.

На **этапе 1** создан минимальный прототип (REPL): диалог с
пользователем, парсер, команды-заглушки и обработка ошибок.

На **этапе 2** эмулятор стал настраиваемым: появились
параметры командной строки (путь к VFS и путь к стартовому
скрипту), отладочный вывод всех заданных параметров при
запуске и исполнение стартового скрипта с остановкой при
первой ошибке.

Приложение реализовано на **Python**, графический
интерфейс — **Tkinter** (входит в стандартную поставку
Python, внешних зависимостей нет).

### Что умеет прототип

- Окно-терминал: тёмная область вывода и строка ввода,
  команда выполняется по клавише `Enter`, введенная строка
  эхо-выводится, как в настоящем терминале.
- Заголовок окна формируется из **реальных данных ОС**, в
  которой исполняется эмулятор, например
  `Эмулятор - [ivanov@MIREA-PC]`:
  пользователь — `getpass.getuser()`, имя узла —
  `socket.gethostname()`.
- Простой парсер: ввод разделяется на команду и аргументы по
  пробелам (и табуляциям).
- Команды-заглушки `ls` и `cd`: выводят своё имя и
  переданные аргументы.
- Команда `exit` завершает сеанс и закрывает окно.
- Обработка ошибок (вывод красным цветом):
  - неизвестная команда — `sh: <имя>: command not found`;
  - неверные аргументы — `exit: too many arguments`
    (у `exit` не может быть аргументов);
  - неверные параметры командной строки — сообщение в
    консоли и код возврата 1 (этап 2).
- **Конфигурация командной строки** (этап 2): `--vfs` —
  путь к физической директории VFS, `--script` — путь к
  стартовому скрипту.
- **Отладочный вывод при запуске** (этап 2): все заданные
  параметры печатаются строками `[debug] ...` в консоль и в
  окно эмулятора.
- **Стартовый скрипт** (этап 2): при запуске эмулятор
  поочерёдно выполняет команды скрипта, на экране
  отображаются и ввод, и вывод (имитация диалога со
  пользователем). Скрипт **останавливается при первой
  ошибке**.
- **Скрипты реальной ОС** (этап 2): `scripts/test_config` и
  `scripts/test_errors` (`.bat` для Windows, `.sh` для
  Linux/macOS) запускают эмулятор во всех режимах для
  проверки всех поддерживаемых параметров.

полностью покрывают юнит-тесты, а графический слой остаётся
тонким.

## 2. Описание всех функций и настроек

### Команды

| Команда | Аргументы | Поведение |
| --- | --- | --- |
| `ls` | любые | заглушка: выводит имя и аргументы, например `ls: args: -la, /home` |
| `cd` | любые | заглушка: выводит имя и аргументы, например `cd: args: ..` |
| `exit` | нет | завершает сеанс, окно закрывается |

### Обработка ошибок

Внутри сеанса (красным в окне):

| Ситуация | Сообщение |
| --- | --- |
| неизвестная команда | `sh: foobar: command not found` |
| `exit` с аргументами | `exit: too many arguments` |
| пустая строка | игнорируется, повторяется приглашение ввода |

При запуске (в консоли, код возврата 1):

| Ситуация | Сообщение |
| --- | --- |
| `--vfs` указывает на несуществующий путь | `error: VFS path does not exist: <путь>` |
| `--vfs` указывает на файл | `error: VFS path is not a directory: <путь>` |
| `--script` указывает на несуществующий файл | `error: startup script not found: <путь>` |
| `--script` указывает на директорию | `error: startup script is not a file: <путь>` |

### Настройки (аргументы командной строки)

| Аргумент | Назначение | По умолчанию |
| --- | --- | --- |
| `--vfs PATH` | путь к физической директории VFS на диске | `vfs/` в корне репозитория |
| `--script PATH` | путь к стартовому скрипту команд эмулятора | не задан (интерактивный режим) |
| `--demo` | выполнить стандартный стартовый скрипт `demo/demo_script.txt` (демо-режим: ошибки не останавливают сессию — показываются все режимы) | не задан |

### Отладочный вывод при запуске

Непосредственно после старта все заданные параметры
печатаются в консоль и выводятся в окне эмулятора:

```
[debug] vfs: D:\repos\Conf_Atrey\vfs
[debug] script: D:\repos\Conf_Atrey\scripts\startup_basic.txt
[debug] demo: no
```

Незаданный параметр отображается как `not set`.

### Стартовый скрипт

Текстовый файл, одна команда эмулятора на строку:

- пустые строки и строки, начинающиеся с `#` (комментарии),
  пропускаются;
- при выполнении на экране отображаются и ввод, и вывод —
  имитация диалога с пользователем;
- скрипт **останавливается при первой ошибке**: команды
  после ошибочной строки не выполняются, после чего
  эмулятор остаётся в интерактивном режиме
  (`script stopped at line N (error)`);
- команда `exit` в скрипте завершает сеанс, как и в
  интерактивном режиме;
- нормально завершённый скрипт сообщает
  `script finished: N command(s)`, и эмулятор остаётся в
  интерактивном режиме.

В репозитории есть два примера: `scripts/startup_basic.txt`
(без ошибок) и `scripts/startup_error.txt` (стоп на первой
ошибке).

### Скрипты реальной ОС (тестирование параметров)

| Скрипт | Windows | Linux/macOS | Содержимое |
| --- | --- | --- | --- |
| тест всех параметров | `scripts\test_config.bat` | `scripts/test_config.sh` | запуски: без параметров, `--vfs`, `--script`, все параметры вместе, `--demo` |
| тест ошибок параметров | `scripts\test_errors.bat` | `scripts/test_errors.sh` | запуски с некорректными `--vfs`/`--script` с проверкой кода возврата (должен быть 1) |

Каждый запуск открывает окно эмулятора; закройте его
командой `exit`, чтобы скрипт перешёл к следующему
сценарию.

## 3. Команды сборки и запуска тестов

Требования: Python 3.9+ (на Linux при отсутствии Tkinter —
`sudo apt install python3-tk`); для тестов — `pytest`.
Сборка не требуется: проект интерпретируемый, артефактов
нет.

| Действие | Команда |
| --- | --- |
| запуск (интерактивно) | `./run.sh` (Linux/macOS) или `run.bat` (Windows), `make run` |
| запуск с параметрами | `python -m src.main --vfs vfs_sample --script scripts\startup_basic.txt` |
| запуск (демо-режим) | `./run.sh --demo` или `make demo` |
| запуск напрямую | `python -m src.main` |
| запуск тестов | `make test` или `python -m pytest -q` |
| тесты параметров (скрипты ОС) | двойной клик по `scripts\test_config.bat` / `bash scripts/test_config.sh` (`make test-os`) |

## 4. Примеры использования

### Запуск со стартовым скриптом (без ошибок)

```
python -m src.main --script scripts\startup_basic.txt
```

В окне (строки `[debug]` — отладочный вывод параметров):

```
[debug] vfs: D:\repos\Conf_Atrey\vfs
[debug] script: D:\repos\Conf_Atrey\scripts\startup_basic.txt
[debug] demo: no
user@PC:~$ startup script: scripts\startup_basic.txt
ls
ls: no args
user@PC:~$ cd /home/user
cd: args: /home/user
user@PC:~$ ls -la /home/user
ls: args: -la, /home/user
script finished: 3 command(s)
user@PC:~$
```

### Остановка при первой ошибке

```
python -m src.main --script scripts\startup_error.txt
```

```
user@PC:~$ ls
ls: no args
user@PC:~$ bad_command
sh: bad_command: command not found
script stopped at line 4 (error)
user@PC:~$
```

Команда `ls -la /home/user` (строка 5 файла) выполнена не
была — скрипт остановился на строке 4. После остановки
эмулятор остаётся в интерактивном режиме.

### Ошибки параметров командной строки

```
$ python -m src.main --vfs no_such_dir
error: VFS path does not exist: no_such_dir
$ python -m src.main --script no_such.txt
error: startup script not found: no_such.txt
```

Код возврата в обоих случаях — 1 (проверяется в
`scripts\test_errors.bat` / `scripts/test_errors.sh`).

### Демо-режим (показ на семинаре)

```
./run.sh --demo
```

Эмулятор сам «вводит» команды из `demo/demo_script.txt`,
последовательно показывая: заглушки `ls`/`cd` без
аргументов и с аргументами, обе ошибки (красным) и
завершение сеанса. В демо-режиме ошибки не останавливают
выполнение — сессия доходит до `exit`, после чего окно
закрывается само. Режим рассчитан на запись экрана.
